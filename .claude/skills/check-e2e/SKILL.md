# check-e2e

`make -C tests/rando test` is the dev loop: unit tests, seconds. `make -C tests/rando e2e` is the net: every case of `tests/rando/cases/` generated by the C port and diffed against the spoiler the VT oracle wrote. It runs once, at the end — here.

A red case is always a bug in the C port. Never run `tests/rando/oracle/gen_golden.sh`, never edit a file of `tests/rando/cases/` to get green.

Every e2e bug leaves behind a unit test that catches it in `make -C tests/rando test`. That is the point: the next time, the dev loop catches it in seconds instead of the net catching it later.

## Rule #1 — never wait on the human

No one answers during this loop. A `QUESTION:` from any sub-agent goes to a fresh `guideline` agent, never to the user. The only way back to the human is the stop after 3 failed attempts (step 5).

## Rule #2 — you are the human at fix-bug's commit gate

`fix-bug` stops once, at its `git-commit` proposal, for a human go-ahead. Here, you give or refuse it, after running the checks of step 4 yourself. Never accept on the strength of an agent's report.

## Loop

### 1. Run the net
Run `make -C tests/rando e2e`. Green → report `E2E-GREEN:` with the list of `fix:` commits made during this run, and stop.

### 2. Split the red into failures
One failure = one `DIVERGENT <case>` line. Keep the full output of each.

Take the baseline case if it is red; otherwise the failure whose RNG trace diverges earliest (attempt, then draw number, from the trace diff): it is the cheapest to diagnose. Handle it alone; the others wait for the next run, since a fix often repairs more than one.

### 3. Invoke fix-bug on it
Invoke the `fix-bug` skill in place. Its argument is a bug report you write, containing:

- **Symptom**, verbatim: the `make -C tests/rando e2e` output for this failure, nothing paraphrased.
- **Reproduction**: `tests/rando/run_e2e.sh <case>`, and the diff of the case's VT trace against the C trace, starting at the first draw that differs. The case's `config.json` says which option it exercises.
- **Constraints on the fix**, to be carried into every stage:
  - The RED test is a **unit test run by `make -C tests/rando test`**, registered in `tests/rando/Makefile`'s `UNIT_TESTS`. Never a new case in `tests/rando/cases/`.
  - Its cost is **negligible**: it builds the minimal world state that reaches the cause, it does not run a whole generation, and it runs well under 50 ms. Needing a full seed to go red is the sign the real cause has not been found — go back to diagnosis, don't ship it.
  - The fix turns **both** the new test and `make -C tests/rando e2e` green.
  - A divergence is a bug. Never regenerate or edit a golden.
- **Already eliminated**, on a retry (step 5): every hypothesis the previous attempts disproved, and why their commit was refused.

### 4. The commit gate — check, then accept or refuse
When `fix-bug` proposes its commit, check each point yourself, with commands you run:

1. The diff adds (or extends) a test under `tests/rando/unit/`, and its binary is in `UNIT_TESTS`.
2. That test reads no file of `tests/rando/cases/` and runs under 50 ms (time it).
3. It **fails on the pre-fix code**: in a throwaway `git worktree` of `HEAD` under `tmp/`, apply only the diff's `tests/` changes, build and run the test — it must fail. Then it passes on the working tree.
4. `make -C tests/rando test` and `make -C tests/rando e2e` are green, and the failure you handed over no longer appears.

All four hold → accept: `fix-bug` commits (folded into `HEAD` when `progress.md` exists, see `git-commit`). Remove the worktree.
Any one fails → refuse, with the reason. Nothing is committed; restore the working tree to `HEAD` before the next attempt.

### 5. Count the attempt
An attempt fails when you refuse the commit, or when `fix-bug` stops on its own (cause unproven after two debug agents, verification failing twice).

- Fewer than 3 failed attempts on this failure → back to step 3 with the same failure, the bug report extended with what was eliminated and why the last attempt failed.
- 3 failed attempts → stop. Report `E2E-FAILED:` to the user: the failure, the three attempts, what each eliminated, and which observation is missing. This is the only moment this skill hands back to the human.

### 6. Loop
After an accepted commit, back to step 1: `make -C tests/rando e2e` from the top.

## Output

- `E2E-GREEN:` + the `fix:` commits made, or folded into `HEAD` (possibly none).
- `E2E-FAILED:` + the report of step 5. The working tree is back at `HEAD`, nothing half-fixed is left behind.

Never push: the caller decides.
